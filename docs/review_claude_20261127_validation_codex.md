## Finding-by-finding verdicts

### 1. Static references lose the creating context — Valid, High (INV-19)

`putstatic_a` converts a current-owner reference into the executing code package. Same-package statics omit the foreign-owner record. When another context executes that library code, the read again tags the reference as current and materializes it through the reader’s heap. A cold read in a separate context is the important case. The stale cache in #19 may instead return a previous value on a warm read. Persist the actual owner identity, including the applet or group scope required by the firewall, and validate it before exposing or materializing the reference. Replacing the code package with another package-sized value alone leaves same-package context identity unresolved. [Store](../choupi/src/jc_bytecodes/bc_static.cpp#L340), [cache and reload](../choupi/src/jc_handlers/jc_static.cpp#L292), [owner elision](../choupi/src/jc_handlers/jc_static.cpp#L357).

### 2. APDU and install references can be stored — Valid, High (INV-13, INV-19)

The APDU buffer and install argument are local arrays, and the APDU object is a local instance. The static and instance stores and reference-array store check the global/temporary designation. Persisting the buffer can promote its backing storage, after which both the input copy and tail clearing can update that persistent body. The number of bytes actually written to flash depends on store behavior and sync, so the extended buffer size is an upper bound on bytes touched, not a measured flash-write count. Mark the buffers global and the APDU instance as a temporary JCRE entry point, with explicit lifetime and clearing. Check all three storage destinations and the SIO argument path. `isTransient` by itself is not the firewall test. [APDU allocation and reuse](../choupi/src/main.cpp#L2720), [APDU instance](../choupi/src/main.cpp#L2804), [install array](../choupi/src/interpretor.cpp#L181), [reference store](../choupi/src/jc_handlers/jc_static.cpp#L334), [persistent byte setter](../choupi/src/jc_types/jc_array.cpp#L720), [JCRE §§6.2.1–6.2.2](https://docs.oracle.com/cd/E59935_01/JCCRE.pdf).

### 3. Package-private virtual-method resolution crosses package boundaries — Partially Valid, Medium (INV-18)

The package-table resolver can follow a superclass into a different package and preflight uses the virtual-method resolver on external references. Dispatch lacks a corresponding package-visibility check. The named ROM method examples and the precise downstream effects depend on the generated method tables and token mapping. Those examples remain unverified. Reject external package-method tokens and scope package-private lookup and override dispatch to the declaring package. Put the check in the shared resolver and preserve legitimate public virtual dispatch across packages. [Resolver](../choupi/src/jc_handlers/jc_class.cpp#L557), [preflight](../src/cap_load.cpp#L964), [runtime dispatch](../choupi/src/jc_bytecodes/bc_invoke.cpp#L438).

### 4. Saved return addresses can exhaust the native heap — Partially Valid, Medium (INV-22)

There is a 256-entry cap per frame. Discarding a return-address operand does not release its slot. The aggregate across live frames remains large and the ARM allocator can panic on exhaustion. The review’s byte estimate and time-to-failure depend on allocator overhead, frame layout, the available heap and #6. They were not demonstrated. A fixed 256-entry array in every frame would impose a large cost even on methods that never use `jsr`. Use a small operation-wide budget, recoverable allocation and a linear free-slot scan. [Save and restore](../choupi/src/frame.cpp#L203), [operand discard](../choupi/src/stack.cpp#L326), [allocator failure](../src/recoverable_allocation.cpp#L83).

### 5. Integer table switch decodes 32-bit bounds as shorts — Valid, Medium (INV-07)

The runtime uses two short fetches for the bounds. The CAP decoder consumes two 32-bit bounds and starts the jump table four bytes later. In-range dispatch can use a bound half-word as an offset. Some executions still produce the correct result, for example when both interpretations select the default branch. Use two int fetches and test both case and default routing, including bounds outside the signed-short range. [Interpreter](../choupi/src/jc_bytecodes/bc_branching.cpp#L1157), [decoder](../src/cap_instruction_boundaries.hpp#L110).

### 6. Signed displacement and width disagree for `jsr` — Valid, High for the boundary guarantee (INV-07, INV-18)

The interpreter turns the signed short into an unsigned value before computing the branch. The decoder consumes two bytes total and validates an 8-bit displacement. That can reject legal targets and misidentify an operand as an instruction boundary when the rest of the stream decodes. Use a signed short, then make the structural and control-flow decoders agree on width and displacement. Include positive tests for both directions as well as a boundary-rejection test. Existing malformed-target coverage alone cannot distinguish rejection for the intended reason. [Interpreter](../choupi/src/jc_bytecodes/bc_branching.cpp#L905), [instruction width](../src/cap_instruction_boundaries.hpp#L59), [branch validation](../src/cap_instruction_boundaries.hpp#L214), [existing fixture](../tests/integration/cap_malformed_vpcd_test.py#L414).

### 7. Abort misses live RAM objects — Valid, High for transaction correctness (INV-14)

An ordinary Java array can be physically RAM-resident before it receives a persistent backing record. Its setter writes the RAM body directly. The abort mechanism restores storage records and advances a rollback generation. It does not restore those RAM values or invalidate all aliases to objects allocated inside the transaction. These are distinct requirements. Use RAM undo for the preexisting objects and track allocations for alias invalidation. Flash promotion would create avoidable writes and still leave the alias problem. The repository directive requires null references after abort. [Array setter](../choupi/src/jc_types/jc_array.cpp#L720), [snapshot bookkeeping](../choupi/src/jc_handlers/flashmemory.cpp#L125), [rollback](../choupi/src/jc_handlers/flashmemory.cpp#L342), [JCRE §§7.6–7.7](https://docs.oracle.com/cd/E59935_01/JCCRE.pdf).

### 8. INSTALL consumes the applet’s transaction slot — Partially Valid, Medium (INV-07, INV-14)

INSTALL opens a runtime storage transaction. The applet-visible depth API reports it as one, begin rejects a second transaction, and applet commit/abort reject a runtime-owned transaction. Oracle permits begin, commit and abort to be no-ops before `Applet.register()`. Before registration, the implementation nevertheless can throw IN_PROGRESS where a no-op would suffice. After registration, applet transaction operations remain blocked until INSTALL completes. Give the applet an isolated transaction or savepoint within the runtime operation and test both sides of registration. Hiding the depth alone would leave the begin and rollback behavior broken. [JCSystem contract](https://docs.oracle.com/cd/E59935_01/api/javacard/framework/JCSystem.html), [INSTALL](../src/cap_load.cpp#L1497), [transaction exclusivity](../choupi/src/jc_handlers/flashmemory.cpp#L667), [JNI](../choupi/src/jni.cpp#L1831).

### 9. CLEAR_ON_DESELECT access checks stop at allocation — Valid, Medium (INV-19)

The allocation check considers applet or install activity. Ordinary array access does not compare the owner context to the selected context. A server running through an SIO can therefore reach its own deselect-transient data while another context is selected. The direct consequence is a transient-lifetime violation, with no demonstrated arbitrary cross-applet access. Enforce the rule on array access, including native-array paths, and retain the permitted install and selection lifecycle cases. [Allocation](../choupi/src/context.cpp#L716), [array lookup](../choupi/src/heap.cpp#L2503), [deselect](../choupi/src/main.cpp#L2575), [JCRE firewall](https://docs.oracle.com/cd/E59935_01/JCCRE.pdf).

### 10. SIO drops some uncaught exception types — Partially Valid, Medium (INV-07)

Explicit Java exceptions that reach `UncaughtJavaException` can already be copied and rethrown. Native-raised exceptions converted inside the interpreter’s catch can lose the uncaught exception record. ISOException takes the status-word path before the boundary, so a non-success reason becomes SecurityException at the client. The blanket title overstates the affected set. Preserve exception identity or permitted exception data at SIO boundaries and map ISO reasons to status words only at the APDU boundary. See missed item B for reason `9000`. [Interpreter catches](../choupi/src/interpretor.cpp#L541), [ISO mapping](../choupi/src/jc_bytecodes/bc_exceptions.cpp#L499), [SIO bridge](../choupi/src/jc_bytecodes/bc_invoke.cpp#L1433).

### 11. Security-sensitive randomness relies on Pico SDK `pico_rand` — Partially Valid, Medium assurance gap (INV-04)

The ARM call sites support the dependency claim. Some API modes have a CTR_DRBG whose seed callback still uses `pico_rand`. ECDH’s callback also serves internal scalar-multiplication randomization, so it should not be described as an ECDH secret-key generator on every call. A software PRNG dependency is a reason to examine entropy and state handling. It does not establish observable ECDSA bias, nonce prediction or a key-recovery result. Check the pinned SDK implementation and board seed assumptions, then use a shared vetted DRBG seeded from an assessed entropy source if stronger assurance is required. SHA-256 conditioning by itself does not establish entropy quality. [RandomData](../choupi/src/native_random.cpp#L68), [DRBG seed callback](../choupi/src/native_random.cpp#L154), [key generation](../choupi/src/native_ec_keypair.cpp#L90), [ECDSA randomness](../choupi/src/native_ecdsa_signature.cpp#L122), [ECDH callback](../choupi/src/native_ec_key_agreement.cpp#L147), [PQC randomness](../choupi/src/native_pqc.cpp#L152).

### 12. Cipher can retain deselect-transient key bytes — Partially Valid, Medium (INV-07)

The symmetric allocator reuses a same-size workspace across clear-event changes. The RSA allocator also compares the event. The symmetric defect can retain a deselect key across deselect or prematurely clear a reset-lifetime key when the transitions are reversed. Fix both directions and wipe the replaced workspace. The ordinary Cipher API explicitly leaves behavior unspecified after the initialized key object is modified. The proposed mandatory `UNINITIALIZED_KEY` after `clearKey()` is therefore too broad. Proactive invalidation of copied key material is a separate hardening decision. INV-21 describes storage placement. [Symmetric workspace](../choupi/src/native_cipher.cpp#L455), [RSA workspace](../choupi/src/native_rsa_cipher.cpp#L379), [Cipher.init contract](https://docs.oracle.com/cd/E59935_01/api/javacardx/crypto/Cipher.html).

### 13. GCM zero IV and post-final reset — Partially Valid, compatibility-sensitive hardening (INV-20)

Both zero-IV paths exist. The claimed conformance defect in the no-parameter overload is **Invalid**. Java Card 3.0.5 expressly specifies zero IV for GCM with the no-parameter overload and describes reset after `doFinal`. Requiring an explicit nonce or re-init as proposed would change the public API behavior. Reusing the same key and nonce for distinct messages is a real security hazard. After explicit nonzero initialization, the first finalization uses the supplied nonce. The zero-IV reuse risk arises on repeated use of the reset state. Document the application’s unique-IV responsibility and test explicit-IV and reset behavior. Any stricter behavior needs an explicit product decision and compatibility accounting. [GCM init](../choupi/src/native_cipher.cpp#L1012), [GCM final](../choupi/src/native_cipher.cpp#L1047), [AEADCipher contract](https://docs.oracle.com/cd/E59935_01/api/javacardx/crypto/AEADCipher.html).

### 14. HMAC key length changes replace the backing array — Valid, Medium (INV-16)

Both setters allocate when the length changes. For persistent keys with persistent backing records, repeated length alternation produces allocation churn and drops the old reference without wiping its payload. Transient keys use transient storage. Reachability deletion and physical flash remanence are separate from logical key clearing. Use capacity-sized storage plus a stored logical length, update all readers of key length, clear the unused tail and handle existing persisted keys. [Public setter](../choupi/src/native_key.cpp#L709), [native setter](../choupi/src/native_key.cpp#L869).

### 15. Unknown AID SELECT deselects the current applet — Valid, Medium (INV-07)

The CCID handler clears secure-channel state and deselects before lookup, then can return `6A82`. A current applet should receive an unmatched applet SELECT as an ordinary command. Resolve the target first and preserve selection for a miss. Preserve same-AID reselection and the separate ISD selection behavior. [Early deselect](../src/ccid_device.cpp#L700), [unknown-AID response](../src/ccid_device.cpp#L1169), [JCRE §4.5](https://docs.oracle.com/cd/E59935_01/JCCRE.pdf).

### 16. Response data and APDU routing — Partially Valid, Medium (INV-07, INV-11)

All three mechanisms are visible in source. Completed output is copied only on `9000`. The exact status/data rule should account for transport and incomplete output, rather than copying the buffer for every failure. Valid GET RESPONSE is intercepted even with an empty VM queue. Card-manager routing also takes sibling applet commands, including `00 CB`, before applet dispatch. Route GET RESPONSE to its pending owner and give unclaimed commands to the selected applet. Keep authenticated management and genuine ISD commands working with the unchanged client. PIV is an illustration of a routing collision, not evidence that the product otherwise supports that applet. [Output gate](../choupi/src/main.cpp#L2871), [GET RESPONSE](../choupi/src/main.cpp#L2688), [CCID routing](../src/ccid_apdu_route.hpp#L60).

### 17. LOAD-only packages miss static-array initialization — Valid, Medium (INV-07)

The only runtime call initializes the package being installed. Successful LOAD makes the package visible without initializing its `array_init` entries. A library with no applet install entry therefore has no normal initializer path. Initialize the package before making it available to other packages, within the LOAD rollback boundary. Preserve existing static state on additional installs and distinguish trusted ROM initialization from dynamic packages. [LOAD](../src/cap_load.cpp#L1306), [INSTALL](../src/cap_load.cpp#L1516), [initializer](../choupi/src/vm_cap_initialization.cpp#L23).

### 18. Normal ARM builds include exception traces — Valid, Medium (INV-24)

`PC_VERSION` distinguishes environments, so the ARM trace blocks survive the normal build switch. The counter saturates at 8 and the `<= 8` sites continue running. The output and lookup overhead are real. USB stall duration is unmeasured. Gate diagnostics with the diagnostic configuration and extend the image check. Fix the budget independently if those diagnostics remain in diagnostic images. Other trace sites are covered in missed item A. [Throw trace](../choupi/src/jc_bytecodes/bc_exceptions.cpp#L155), [budget increment](../choupi/src/jc_bytecodes/bc_exceptions.cpp#L226), [frame trace](../choupi/src/jc_bytecodes/bc_exceptions.cpp#L288), [interpreter traces](../choupi/src/interpretor.cpp#L541), [existing check](../tools/test-no-debug-traces).

### 19. Static-reference cache can return overwritten values — Valid, Medium (INV-07, INV-19)

The cache is per shared heap storage, so individual heap wrappers can share entries. Distinct heap-storage groups can cache the same global static slot independently. A successful write updates only the writer’s cached entry. Rollback generation prevents reuse after rollback and does not invalidate another group’s entry after a successful write. A warm reader can therefore see a stale value and retain a stale root. Invalidate all affected entries on successful write or use a slot version. A single cached heap-local reference cannot safely be shared across unrelated heaps. [Shared storage](../choupi/src/heap.cpp#L129), [lookup and generation check](../choupi/src/heap.cpp#L1234), [cache update](../choupi/src/heap.cpp#L1271), [read order](../choupi/src/jc_handlers/jc_static.cpp#L300).

### 20. VM-created exceptions depend on package imports — Partially Valid, Medium (INV-07)

SystemException and APDUException search only the current frame package’s imports and throw if a matching entry is missing. CryptoException instead uses the applet package's imports. Both mechanisms make the runtime’s ability to construct an exception depend on unrelated linkage metadata. A framework frame that lacks the framework import hits this path. The exact per-profile ROM Import bytes and the AID allocation example remain unverified. The same import dependency affects Java-language exceptions, so use trusted ROM package and class identity for those as well. Preserve native reason values. [Import lookup](../choupi/src/jc_bytecodes/bc_object.cpp#L239), [crypto lookup](../choupi/src/jc_bytecodes/bc_object.cpp#L271), [exception dispatch](../choupi/src/jc_bytecodes/bc_object.cpp#L305).

### 21. Applet-defined ISOException subclasses lose the reason status — Valid, Low (INV-07)

The subclass check runs inside a framework-package AID check, which excludes instances whose actual class belongs to the applet’s package. The unmatched top-level throw then takes the generic failure path. Empty-stack undefined behavior in #25 makes the final outcome less predictable than a guaranteed `6F00`. Test assignability to the trusted ISOException class independently of the object's package, then extract the reason only at the APDU boundary. [Package gate and status mapping](../choupi/src/jc_bytecodes/bc_exceptions.cpp#L470).

### 22. A thrown exception from `select()` can escape as its own status word — Valid, Low to Medium (INV-07)

The VM returns a non-success status from the callback unchanged, and CCID sends it to the host. Java Card 3.0.5 requires `6999` when the callback rejects selection or throws. Apply this mapping at the selection callback boundary. The later `process(SELECT)` call has its own response rules. Distinguish callback exceptions from internal storage errors in diagnostics. [Selection callback](../choupi/src/main.cpp#L2524), [CCID response](../src/ccid_device.cpp#L1116), [JCRE §4.5](https://docs.oracle.com/cd/E59935_01/JCCRE.pdf).

### 23. APDU state, length and Util argument validation — Partially Valid, Low to Medium (INV-07)

- **Outgoing length and reasons — Valid.** The backing buffer bounds outgoing length and the no-chaining path adds a 252-byte bound. There is no separate 256-byte short-applet ceiling and native APDU exceptions use reason 1. Check applet capability and preserve `BAD_LENGTH` separately from state errors. [Length validation](../choupi/src/context.cpp#L1057), [reason mapping](../choupi/src/jc_bytecodes/bc_object.cpp#L405), [APDUException contract](https://docs.oracle.com/cd/E59935_01/api/javacard/framework/APDUException.html).
- **`receiveBytes` — Valid for validation.** Returning zero after the buffered input is exhausted is reasonable. The implementation also returns zero in invalid states and never checks the offset. Keep the buffered transport and enforce the API preconditions. [ROM API implementation](../choupi/javacard-sdk/javacard-api/src/javacard/framework/APDU.java#L602), [APDU contract](https://docs.oracle.com/cd/E59935_01/api/javacard/framework/APDU.html).
- **`setOutgoing` without Le — Unverifiable as a baseline defect.** Short case 1/3 APDUs lack an expected response length. The project’s T=1-oriented implicit-Le extension is specific to extended applets. A short case 1/3 command has no response-data phase in its nominal encoding, so an applet relying on a response there needs a protocol or product-specific justification. [State check](../choupi/src/context.cpp#L1044), [implicit Le](../choupi/src/main.cpp#L2751), [JCRE transport cases](https://docs.oracle.com/cd/E59935_01/JCCRE.pdf).
- **Util validation — Valid, with wider reach.** External `arrayCopyNonAtomic` and `arrayFillNonAtomic` get the native interception. `arrayCompare` does not. Its ROM loop can therefore return success for null or negative-length inputs from an applet and can return on the first difference before examining the full requested range. Validate arguments before iterating, including the zero-length and early-difference cases. [Interception list](../choupi/src/jc_bytecodes/bc_invoke.cpp#L915), [comparison](../choupi/javacard-sdk/javacard-api/src/javacard/framework/Util.java#L434).

### 24. An atomic Util failure can leave its implicit transaction open — Valid, Medium (INV-14)

The ROM methods start an applet-visible transaction when depth is zero, then write and commit without an exceptional cleanup path. At least `setShort` directly uses bytecode stores. A sufficiently large existing persistent record can exceed capacity when the first byte is written, even for a two-byte update, since capacity is charged on the record snapshot. The snapshot vector is sized before the capacity check. An applet catching the error can observe the leaked depth and its next transaction can fail. Check whether this call owns the implicit transaction before aborting. Preserve caller-owned transactions and check the charge before allocating the snapshot. Native atomic range handling should preserve the distinction between atomic and explicitly non-atomic APIs. [ROM copy](../choupi/javacard-sdk/javacard-api/src/javacard/framework/Util.java#L107), [ROM setShort](../choupi/javacard-sdk/javacard-api/src/javacard/framework/Util.java#L533), [snapshot allocation and charge](../choupi/src/jc_handlers/flashmemory.cpp#L125), [process cleanup](../choupi/src/main.cpp#L2910).

### 25. Exception exit can dereference an empty frame list — Valid, High (INV-22)

An uncaught throw can pop the last frame, then throw a VM enum into the interpreter catch. The ARM catch first reads operands through the current frame. There is also an unguarded stack-depth read outside the ARM diagnostic guard, and some branches read PC through the current frame. ISO status and captured-object catches have separate paths, so the failure does not affect every uncaught exception. Current symptoms cannot be inferred from undefined behavior. Preserve the failing PC and operand depth before dispatch, then guard every post-unwind frame-dependent access on both builds. [Unwind](../choupi/src/jc_bytecodes/bc_exceptions.cpp#L462), [enum catch and post-dispatch diagnostics](../choupi/src/interpretor.cpp#L563), [unchecked frame accessor](../choupi/src/stack.cpp#L980).

### 27. Throwable verification and raw saved crypto state — Partially Valid, Low (INV-18)

**Throwable — Valid.** The throw path checks nulls, arrays and ownership but does not require Throwable assignability. The SIO bridge can allocate an instance of the supplied class and rejects private reference fields during the copy. Validate the throw before dispatch and check transferability before allocating the copy.

**Saved crypto state — Partially Valid.** The code does restore internal crypto state from private workspaces, and some fields lack independent range checks. The uploaded-field gate blocks direct access to the cited ROM fields. A corrupt-state crash or cross-context escape remains unverified. Check critical saved-state invariants at deserialization, with priority given to offsets and sizes that feed memory operations. [Throw checks](../choupi/src/jc_bytecodes/bc_exceptions.cpp#L179), [SIO copy](../choupi/src/jc_bytecodes/bc_invoke.cpp#L160), [ROM field gate](../choupi/src/jc_bytecodes/bc_object_field.cpp#L157), [CCM](../choupi/src/native_cipher.cpp#L1086), [SHA-3](../choupi/src/native_message_digest.cpp#L126), [CTR_DRBG](../choupi/src/native_random.cpp#L186), [SHAKE](../choupi/src/native_pqc.cpp#L1062).

### 28. Static-field component helpers compute wrong offsets — Valid, cleanup

The unused inline helpers treat the array initializers as fixed-size records and use the serialized count directly. Variable-length payloads and endian conversion make those offsets wrong for real components. No runtime caller was found. Delete the helpers after checking out-of-tree consumers if the header is shared. [Unused helpers](../choupi/src/jc_cap/jc_cap_static_field.hpp#L62), [live initializer](../choupi/src/vm_cap_initialization.cpp#L23).

## Significant missed issues

1. **A. Normal-mode logging extends beyond exceptions — Medium (INV-24).** CCID prints a raw prefix of each `00 A4` request before checking the SELECT command shape, then emits selection diagnostics and flushes stdout. The interpreter also publishes a non-diagnostic VM progress line. This widens the normal-image violation beyond #18 and exposes command contents on the logging interface. Gate these sites and check the resulting normal image for the corresponding strings. [Raw CCID log](../src/ccid_device.cpp#L690), [selection diagnostics](../src/ccid_device.cpp#L1069), [VM progress log](../choupi/src/interpretor.cpp#L518).
2. **B. SIO status `9000` can hide a thrown ISOException — Medium (INV-07).** The same status conversion identified in #10 also has a success edge. The server interpreter returns the reason as the status and the bridge treats `9000` as normal completion, falling through to return-kind handling. This loses the exception without taking the error branch described by Claude. Keep native return status, Java exception and host status word distinct. [ISO status conversion](../choupi/src/jc_bytecodes/bc_exceptions.cpp#L499), [interpreter ISO catch](../choupi/src/interpretor.cpp#L554), [SIO return handling](../choupi/src/jc_bytecodes/bc_invoke.cpp#L1433).
3. **C. Randomness review omitted the card manager and RSA-CRT blinding — Medium assurance gap (INV-04, INV-11, INV-20).** SCP03’s ARM challenge uses `get_rand_128()` and RSA-CRT blinding uses `get_rand_32()`. Include both in any entropy-source audit and migration. This is a verified dependency, with no demonstrated prediction or protocol break. [SCP03 challenge](../src/scp03.cpp#L238), [RSA-CRT callback](../choupi/src/native_rsa_math.hpp#L44).
4. **D. `JCSystem.isTransient(null)` throws — Low (INV-07).** The native function throws before returning the memory type. The public API lists a default result of `NOT_A_TRANSIENT_OBJECT` and declares no null exception. The 3.0.5 text does not name null explicitly. Return that value and extend the existing transaction applet probe. [JNI](../choupi/src/jni.cpp#L1578), [existing tests](../tests/integration/jcsystem_transaction_applet_test.py#L278), [JCSystem API](https://docs.oracle.com/cd/E59935_01/api/javacard/framework/JCSystem.html).

The `arrayCompare` applet-call path in #23 and repeated linked-list traversal in #4 also broaden the original findings. Separately, the three issues Claude deliberately excluded are already recorded in the [companion review](review_20261127.md).

## Product invariant and evidence scope

- **INV-01–06.** The findings target ARM and native JCVM execution. INV-03 has an existing scope discrepancy if read literally for every API method. The checked-in framework contributes executable Java API bytecode, including Util atomic sequencing and APDU methods. The algorithm implementations reviewed here are native. INV-04 randomness assurance is covered above. Core scheduling and physical CCID enumeration remain outside this validation. [Framework Util](../choupi/javacard-sdk/javacard-api/src/javacard/framework/Util.java#L92), [product specification](../SPEC.md#L18).
- **INV-07–12.** API compatibility and APDU limits are covered above, including the short-applet response ceiling relevant to INV-09. Changes to routing must preserve INV-11. Reporting parity, shipped card contents and the release treatment of the SCP03 test key were outside this review. [Product specification](../SPEC.md#L50).
- **INV-13–16.** APDU storage and transaction defects are covered above. Stale roots and HMAC replacement can harm reclamation and storage plateau. The complete GC trace and power-tear guarantees were outside this review. [Product specification](../SPEC.md#L100).
- **INV-18–22.** The report identifies concrete boundary, firewall and malformed-input gaps. Side-channel and secret-copy findings have the best-effort scope specified by INV-20. INV-21 defines present key storage and a future protected store. It does not by itself require physical erasure of obsolete records. [Product specification](../SPEC.md#L126).
- **INV-23–28.** Debug code in the normal ARM build is a source-level INV-24 violation. Per-profile compiled contents and image identity, pinned-fixture execution, acceptance and capacity measurements remain unverified. INV-17 and INV-29 are intentionally unused. [Product specification](../SPEC.md#L161).

**Evidence limits.** This was a read-only code review apart from this report. No firmware build, test run, simulator or hardware reproduction was performed. ROM-profile-specific reachability, exact memory and flash costs, and timing effects remain unmeasured.
